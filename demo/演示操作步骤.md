## 三、第一段：从已有材料展示抽取结果

### 1. 项目管理

进入“项目管理”，点击 `test01` 的“进入项目”，再回到“评估总览”。

讲解可以这样说：

> 每次评估先建立独立项目，后续上传的证据、抽取结果、资产图谱、风险计算、复核、整改和审计记录都按项目隔离。

不要为了这次录屏重新创建项目；现有项目已经包含完整演示数据。

### 2. 证据采集与抽取

进入“证据采集与抽取”，逐条打开材料记录，展示文件名、处理状态、来源和置信度：

| 材料 | 当前置信度 | 演示重点 |
| --- | ---: | --- |
| `01_CMDB资源台账.xlsx` | 0.70 | 平台主机、资源池、虚拟化和安全控制 |
| `02_虚拟化集群与VM承载清单.xlsx` | 0.85 | 计算节点、虚拟机、账号和业务承载 |
| `03_网络拓扑图.pdf` | 0.60 | 网络分区、访问路径和失效关系 |
| `04_应用数据库业务承载清单.xlsx` | 0.90 | 应用、数据库、政务服务事项和数据敏感度 |

点击其中一条材料的“查看抽取”，重点展示：

- 候选资产和关系；
- 来源文件；
- 置信度；
- 风险源；
- 待确认问题。

讲解要点：

> 普通 Excel、JSON、DOCX、PDF 先作为评估材料保存；模型从材料中提出候选资产、关系和风险，服务端校验字段、枚举、来源和置信度后才写入图谱。抽取失败会保留为“待处理”，不会用假数据补进去。

### 3. 跨层资产图谱

进入“跨层资产图谱”，展示平台、租户业务和安全控制三类节点。可以优先指出：

- `H01`：云平台主机；
- `V1`：虚拟化资源池或组件；
- `VM-A1`：承载业务的虚拟机；
- `DB-A`：应用数据库；
- 政务服务事项：租户侧重要业务；
- `U01`：权限或账号风险源；
- `R01`：安全控制节点。

然后打开关系表，展示承载、挂载、部署、调用、网络、权限、共享资源和隔离关系。灰色或虚线关系表示普通依赖或已经失效的关系，红色有效边用于解释风险传播路径。

这里要特别说明：

> 图谱默认由评估材料自动分析生成，不要求先填写模板。只有需要补充遗漏资产、关系或风险源时，才在本页使用“补充上传 Excel 图谱”，下载模板后填写并导入。

如果要演示人工修订，点击一个节点的“修订属性”，修改业务重要性、数据敏感度或安全措施，填写修订理由并保存。关系表中的“修订”可以切换有效状态并调整 C/N/P/R/E/B/I 因子。

### 4. 风险穿透计算

进入“风险穿透计算”，点击“重新执行穿透计算”。

先看顶部摘要：

- 有效路径数量；
- 被阻断候选路径数量；
- 失效或超出有效期的边数量；
- 待补全槽位数量。

再打开 `U01 → DB-A` 或一条 P1 风险的“明细”，展示：

- 完整穿透路径；
- C、N、P、R、E、B、I 七个穿透因子；
- `S`、`Tp`、`Pt`、`Lt`、`Rt`；
- 风险等级和优先级；
- 证据链；
- 处置建议。

可以用一句话解释规则：

> 模型负责从材料中抽取和归纳，路径是否有效、风险值和风险等级由规则引擎计算，人工复核可以留下前值、后值、理由、人员和时间。

点击“计算参数”可展示默认演示参数：穿透因子等权、`α=0.5`、损失因子等权、等级阈值 `0.2 / 0.4 / 0.6 / 0.8`。现场只查看即可，除非要专门展示参数调整。

## 四、第二段：槽位追问和人工复核

### 1. 聚焦复核队列

进入“聚焦复核队列”，展示系统为什么把某些路径放入复核范围：

- 高或很高风险；
- 涉及敏感数据或重要业务；
- 多跳跨层路径；
- 接近风险阈值；
- 低置信度、冲突证据或关键关系缺失。

右侧会看到待补全问题。选择一个问题，输入类似：

> 该权限关系当前有效，已于 2026-10-20 完成复核，责任人为安全管理员。

点击“写回槽位并重算”。系统会更新槽位，必要时更新关系有效性，并重新计算相关风险。

如果要展示模型生成追问，点击“模型优化追问”。页面会显示自然语言问题；模型不可用时会保留原问题并提示错误，不能把错误结果当成成功抽取。

### 2. 人工复核回写

在风险列表打开一条高风险项，点击“复核”：

1. 选择“风险等级”或“风险值”；
2. 填写人工确认后的值；
3. 填写依据，例如“结合补充的权限审计记录确认”；
4. 点击“确认回写”。

回写后再打开“审计轨迹”，可以看到修改前后值、复核人、时间和理由。回到风险页刷新，可以看到人工复核后的结果。

## 五、第三段：整改、审计和报告

### 1. 整改任务

进入“整改任务”，展示系统根据 P1-P3 风险自动生成的任务，包括：

- 优先级；
- 任务标题；
- 关联风险；
- 责任人；
- 截止日期；
- 处置建议；
- 当前状态。

现场可以将一条任务标记为“已完成”，然后刷新页面，展示状态变化。

### 2. 审计轨迹

进入“审计轨迹”，按时间展示：

- 项目创建和切换；
- 材料上传；
- 模型抽取成功或失败重试；
- 风险计算；
- 槽位回答；
- 节点或关系修订；
- 风险复核回写；
- 报告生成。

这页用于证明每个关键操作都有留痕。

### 3. 生成 LLM 评估报告

点击页面右上角“生成评估报告”。

页面会先显示处理中状态，完成后打开报告窗口。报告中的文字由模型整理，但以下内容以系统已经校验的结果为准：

- 风险数值；
- 风险等级；
- 穿透路径；
- 证据数量和状态；
- 人工复核结果；
- 整改任务事实。

报告窗口重点展示“评估摘要”“总体结论”“主要发现”“整改建议”“证据质量”和“局限与后续”。生成失败时页面会显示错误，可以检查模型配置后再次点击生成，不会保存一份伪造报告。

### 4. 导出规则报告 PDF

报告生成后或页面右上角点击“导出 PDF”。PDF 是规则引擎生成的确定性报告，适合作为预审配套材料，包含：

- 项目名称和评估范围；
- 有效路径与阻断路径摘要；
- 路径和公式计算明细；
- 风险等级和优先级；
- 证据链；
- 复核记录；
- 整改建议。

LLM 报告和规则 PDF 是两个结果：前者负责把已校验数据整理成自然语言，后者负责提供可重复核对的结构化计算证据。

2. 进入“证据采集与抽取”，从本机材料目录逐个选择文件：
   - `01_CMDB资源台账.xlsx`
   - `02_虚拟化集群与VM承载清单.xlsx`
   - `03_网络拓扑与安全策略.pdf`
   - `04_应用数据库业务承载清单.xlsx`
   - `05_云平台权限与审计日志.json`
   - `06_迁移变更单与操作记录.docx`
   - `07_虚拟化与主机漏洞扫描报告.pdf`
   - `08_备份加密与安全控制核查记录.docx`
3. 每上传一份材料后，点击“调用模型抽取”。右侧“模型解析过程”会按阶段显示文件读取、请求提交、等待响应、结构化校验和写入结果，按钮会暂时禁用。

`03_网络拓扑图.pdf` 是用于展示扫描/图形材料待处理状态的可选材料。如果当前服务器能够提取其中的文字，它也可能正常进入抽取流程；不要把“待处理”解释成系统故障。

## 七、推荐录屏顺序和讲解词

建议录屏按下面顺序，一次完成主线：

> 登录 → 选择 `test01` → 总览基线 → 查看 4 份材料和抽取结果 → 查看跨层资产图谱 → 展示失效边 → 执行风险计算 → 打开 `U01 → DB-A` 明细 → 回答一个槽位 → 人工复核一条风险 → 查看整改任务 → 查看审计轨迹 → 生成 LLM 评估报告 → 导出 PDF。

开场可以说：

> 这是一个按评估项目隔离的云计算跨层风险穿透评估工作台。系统不预置业务资产，资产、关系和风险证据来自本次项目材料；模型负责抽取候选结果，服务端负责校验，规则引擎负责路径和风险计算，人工复核负责闭环确认。

结尾可以说：

> 本次演示完成了从多源证据采集、模型抽取、跨层图谱构建，到路径识别、风险计算、槽位追问、人工复核、整改和报告输出的完整链路。

## 八、常见情况处理

| 现象 | 处理方式 |
| --- | --- |
| 总览显示“请先创建项目” | 在顶部“当前项目”选择 `test01`，或进入项目管理点击“进入项目”。 |
| 图谱没有节点 | 先确认当前项目正确，再刷新；没有通过抽取校验的材料不会进入图谱。 |
| 风险列表为空 | 进入风险页点击“重新执行穿透计算”，并确认图谱中存在有效关系。 |
| 模型按钮点击后没有立即结果 | 观察右侧“模型解析过程”；模型调用可能需要等待，按钮在处理期间会禁用。 |
| 模型抽取失败 | 保留失败状态和错误日志，检查服务配置后点击同一材料的抽取按钮重试。不要手动宣称抽取成功。 |
| 生成报告失败 | 检查模型服务地址、模型名和服务可达性，确认项目已有通过校验的证据和风险结果后重试。 |
| 数量和本文基线不同 | 说明现场已经进行了槽位回答、复核、任务完成或重新计算，审计轨迹会保留这些变化。 |
| 需要证明数据持久化 | 在测试机执行 `cd /home/dq/cloud-risk-penetration-assessment/demo && docker compose restart`，刷新页面确认项目、材料和结果仍在。 |
