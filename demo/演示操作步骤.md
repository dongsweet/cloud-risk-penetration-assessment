## 建议采用两段录制

这个安排合适，而且两段的目的不同：第一段用已有的 `test00` 快速介绍系统和结果页面；第二段新建项目，从上传原始材料开始录真实模型抽取和业务闭环。这样既能先有一段稳定的“系统全貌”，也能单独证明新项目可以从材料开始跑完整流程。第一段只浏览，不改动 `test00`。

照读版台词见 [`录屏讲稿.md`](录屏讲稿.md)。

- 录屏一：`01_系统全貌_test00`，约 2–3 分钟。
- 录屏二：`02_新项目完整流程`，按模型响应速度录制，可分段完成。
- 建议登录账号：`test01`；演示项目：`test00`。
- 系统地址：`http://172.20.30.201:17001`。

## 录制前准备

1. 浏览器打开系统，确认能正常登录。先确认当前项目列表中有 `test00`。
2. 确认 `test00` 的总览、图谱和风险页已有内容；这段只展示已有结果，不重新计算、不回答追问、不复核、不完成整改。
3. 在项目管理中确认可以新建项目；录屏二会创建一个新项目，不要在 `test00` 里上传材料。
4. 确认模型服务可用。可打开 `http://172.20.30.201:17001/health` 看服务健康状态；不要打开或录入 `.env` 中的 API 密钥。
5. 打开本机 `测试证据包` 文件夹，确认下方 01–08 材料在场。`00_上传顺序与核对清单_请勿上传.txt` 仅供自己核对，不要上传。
6. 全屏浏览器并关掉无关窗口、通知和终端。录制中模型响应较慢时，保留界面显示的步骤进度；不要把失败状态说成成功。

## 录屏一：用 test00 介绍系统全貌

目标是快速让观看者知道系统有哪些部分，以及各部分如何衔接。`test00` 是已有数据的展示项目；这段不证明新材料的实时抽取。

1. 登录后在“当前项目”选择 `test00`，进入“评估总览”。
2. 展示项目名称、证据数量、资产和关系、风险路径、待补全问题等总览信息。数量以录制当时页面实际显示为准，不必背固定数字。
3. 进入“证据采集与抽取”，展示几份已上传材料的文件名、抽取状态和置信度；打开一份“查看抽取”，看候选资产、关系和来源。
4. 进入“跨层资产图谱”，展示平台侧、租户业务侧和安全控制节点，以及有效/失效关系。点明来源展示的是可读文件名，内部编号用于追踪。
5. 进入“风险穿透计算”，打开一条实际存在的风险明细，展示穿透路径、因子、公式、等级和证据链。
6. 快速扫过“聚焦复核队列”“整改任务”“审计轨迹”。只展示现有记录，不提交表单、不更改任务状态。
7. 如果 `test00` 已有评估报告，可以打开看一下；如果没有，就略过，把报告留到录屏二现场生成。

开场可以这样说：

> 先用已有的 `test00` 项目快速介绍工作台。系统按项目管理评估材料、跨层资产关系、风险计算、人工复核、整改和审计记录；接下来我会新建一个项目，从原始材料开始演示实际处理流程。

## 录屏二：新建项目并演示完整业务流程

### 1. 新建评估项目

进入“项目管理”点击“新建项目”，建议填写：

- 项目名称：`政务云跨层风险评估-全流程演示`
- 评估范围：`云平台主机与虚拟化集群、租户虚拟机、应用和数据库、账号权限、网络隔离及备份安全控制。`

创建后进入该项目。确认项目是空的，再开始上传；空项目没有资产和风险是正常现象，图谱数据要等本项目材料抽取通过校验，或补充导入的 Excel 图谱模板通过校验后才会出现。

### 2. 上传独立证据并逐份调用抽取

从本机 `测试证据包` 按下面顺序逐份上传。每份上传后点击“调用模型抽取”，右侧显示解析进度时稍等其完成，再查看抽取结果；避免对同一份已成功材料重复调用。

1. `01_CMDB资源台账.xlsx`
2. `02_虚拟化集群与VM承载清单.xlsx`
3. `03_网络拓扑图.pdf`
4. `04_应用数据库业务承载清单.xlsx`
5. `05_云平台权限与审计日志.json`
6. `06_迁移变更单与操作记录.docx`
7. `07_虚拟化与主机漏洞扫描报告.pdf`
8. `08_备份加密与安全控制核查记录.docx`

每份抽取完成后，查看候选资产或关系、来源文件和置信度。抽取过程以页面实际返回为准：有冲突或缺失时展示系统生成的待确认问题；如果某份失败或超时，就展示失败状态并重试，不要手工补写成模型已经抽取成功。

### 3. 查看图谱并执行风险计算

1. 进入“跨层资产图谱”，展示本项目通过校验后生成的资产节点、关系、材料来源和置信度。
2. 如果图谱仍为空，先回到材料页检查抽取状态；没有通过校验的结果不会进入图谱。需要补充关系时，可在图谱页下载并填写 Excel 模板后补充上传。
3. 进入“风险穿透计算”，点击“重新执行穿透计算”。打开一条实际生成的风险明细，展示路径、C/N/P/R/E/B/I 因子、公式计算值、风险等级和证据链。
4. 数量和风险等级按当次模型抽取及规则计算的实际结果介绍，不要引用旧项目的统计数字。

### 4. 演示槽位追问和人工复核

1. 打开“聚焦复核队列”，优先选择“关系有效状态冲突待确认”或“低置信度关系待确认”，这样可以展示关系状态回写和风险重算；若没有这类问题，再选择其他实际待确认项。证据引用应显示文件名，可带括号中的内部编号。
2. 根据该问题关联的材料原文填写确认结果。无法从材料确认的内容，就写明“现有材料无法确认，继续列为待核实”，不要猜测。
3. 点击“写回槽位并重算”。关系有效状态类追问会更新关系并触发重算；其他追问会保存回答和审计记录，按页面实际结果介绍。
4. 回到风险列表，选择一条实际存在的高风险或需要复核项，填写复核结论及理由并保存；再到“审计轨迹”展示人员、时间和修改记录。

### 5. 演示整改记录、报告和审计

1. 进入“整改任务”，选择一条未完成任务，点击“提交整改记录”。
2. 因本项目使用虚构演示材料，若要演示完成动作，建议明确写成模拟操作，例如：

   - 整改措施和处理结果：`演示整改：按该任务处置建议完成模拟配置调整，并记录于本次演示变更记录。`
   - 验证方法和验证结果：`演示验证：对照任务要求复查相关配置和审计记录，确认模拟整改项符合处置要求。`
   - 佐证材料或记录编号：`DEMO-CHG-001（模拟记录）`

   两个必填说明都需要至少 8 个字符。提交后任务才会标记完成，并记录提交人、时间和说明；不要把模拟操作描述成真实生产环境已执行的整改。

3. 点击“生成评估报告”，展示四个串行模型步骤、各步骤进度和最后的报告。重点介绍摘要、主要发现、整改建议、证据质量与局限。
4. 点击“导出 PDF”，保存规则计算报告；再打开“审计轨迹”，展示抽取、计算、追问、复核、整改和报告生成记录。

结尾可以这样说：

> 这个新项目从独立材料上传开始，经过模型抽取和服务端校验，形成跨层关系并由规则引擎计算风险；待确认事项可以写回，人工复核和整改记录会留下审计轨迹，最后生成评估报告和 PDF。

## 时间紧张时的取舍

完整录制建议使用全部 8 份材料。如果今天时间有限，第二段优先演示 `01_CMDB资源台账.xlsx`、`02_虚拟化集群与VM承载清单.xlsx`、`04_应用数据库业务承载清单.xlsx`、`05_云平台权限与审计日志.json`，用表格和日志材料先走通上传、抽取、图谱、风险、追问、复核和报告；其余材料可展示在待上传列表或之后补录。不要为了赶时间把未抽取材料说成已进入图谱。

模型等待时间较长时可以分段录制：先录上传和右侧解析过程，等任务结束后再录结果页面；后期拼接时保留实际状态和结果，不要剪成与事实不符的成功过程。

## 两段录屏的界限

| 内容 | 录屏一：test00 | 录屏二：新项目 |
| --- | --- | --- |
| 用途 | 快速介绍系统和主要页面 | 证明从原始材料到评估输出的操作闭环 |
| 数据 | 已有演示数据 | 本次新建项目的上传材料和实际抽取结果 |
| 操作 | 浏览为主，不做写入 | 新建、上传、抽取、计算、复核、整改和报告 |
| 关键说明 | 展示预先准备好的总体效果 | 展示本次项目实际产生的过程和结果 |

所有演示材料均为虚构样例；录屏中可说明这是功能可行性演示，不对应真实生产环境。
